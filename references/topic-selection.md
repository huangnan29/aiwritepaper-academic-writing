# 无选题与模糊方向的选题工作流

## 一次性采集信息

当用户没有题目时，一次询问：

- 专业；
- 专业细分方向；
- 论文层次与预计字数；
- 可获得的数据、源码、图纸、实验条件、问卷、访谈、病例、案例或文本；
- 偏好的研究方式；
- 学校、导师或期刊明确禁止的方向。

用户只提供大概方向时，先基于已知信息推断，不重复询问已经给出的内容。

## 生成 10 个题目

每个题目必须给出：

| 字段 | 要求 |
|---|---|
| 题目 | 对象、问题和方法清晰，不堆砌技术名词 |
| 核心研究问题 | 一句话且可回答 |
| 方向提示词 | 指向一个 `compiled-prompts` 文件 |
| 方法 | 与可用材料一致 |
| 所需证据 | 明确到数据、代码、文献或原始材料 |
| 可行性 | 高、中、低，并说明原因 |
| 主要风险 | 数据、伦理、时间、工具、范围或创新风险 |
| 降级题目 | 材料不足时可改成的诚实版本 |

## 推荐原则

- 至少 6 个题目应在用户现有资源下具有高或中等可行性。
- 不把需要无法获得的企业内部数据、病例、伦理审批或昂贵设备的题目伪装成容易完成。
- 没有真实数据时，优先推荐文献综述、公开数据研究、规范分析、文本研究、设计方案或验证协议。
- 没有源码和运行环境时，不推荐声称“已实现并完成性能测试”的系统论文。
- 避免题目过大，例如“中国经济发展研究”“人工智能对教育的影响”。
- 避免先写结论式题目，除非结论已有数据支持。
- 十个题目应覆盖不同研究问题或方法，不做同义替换。

## 确定后的动作

用户选定题目后，重新执行 `routing.md`。必须先确认方向提示词和证据边界，再进入大纲或正文生产。
